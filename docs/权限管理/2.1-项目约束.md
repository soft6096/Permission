# 项目约束 - 权限管理

## 技术架构总览

| 类别 | 选型 | 版本 | 说明 |
|------|------|------|------|
| 开发框架 | Spring Boot | 3.2.5 | 服务端基础框架 |
| 语言 | Java | 17 | 全模块统一 |
| ORM | MyBatis-Plus | 3.5.7 | 数据访问 |
| 数据库 | MySQL | 8.0 | InnoDB，utf8mb4 |
| 缓存/会话 | Redis | 7.x | 存储登录 token（有状态凭证） |
| JWT | jjwt | 0.12.5 | 签发 token |
| 密码加密 | spring-security-crypto（BCryptPasswordEncoder） | 随 Spring Boot 6.2.x | bcrypt 单向加密 |
| 工具 | Lombok | 随 Spring Boot BOM | @Slf4j/@Data |
| 构建 | Maven | 3.9.x | 单模块 + 分层分包 |

> 单模块工程（小项目不强行多模块），按包分层：`controller / service / mapper / domain / config / common / init`。
> 包根：`com.permission`。

## 硬性约束（AI 编码时必须遵守）

1. 数据访问统一 MyBatis-Plus（BaseMapper + ServiceImpl），禁止原生 JDBC/JdbcTemplate
2. 5 张表命名固定：`sys_user`、`sys_role`、`sys_permission`、`sys_user_role`、`sys_role_permission`，库字符集 utf8mb4
3. 密码必须用 BCryptPasswordEncoder 加密存储，禁止明文、禁止 MD5/SHA 自实现
4. 数据库操作统一走 Service 层，Controller 禁止直接调用 Mapper
5. 涉及多表写入的方法必须加 `@Transactional`，事务只放 Service 层，禁止放 Controller
6. 统一返回体 `R<T>`（code/message/data），禁止直接返回 Map/裸对象；分页用 `PageResult<T>`（total + records）
7. 业务码统一约定（全局枚举 `ResultCode`）：
   - `200` 成功、`400` 参数错误、`401` 未登录、`403` 无权限、`404` 不存在、`500` 系统错误
   - `1001` 用户名或密码错误、`1002` 用户被禁用、`1003` 用户名已存在、`1004` 角色编码已存在、`1005` 旧密码错误、`1006` admin 保护操作被拒、`1007` 强制改密未完成
8. 实体/字段命名：Java 驼峰，表字段下划线，表名固定 `sys_` 前缀
9. 禁止 System.out.println，统一 Lombok @Slf4j
10. 所有时间字段用 DATETIME，禁止字符串存时间
11. 认证凭证：JWT 签发 token + Redis 存储，Redis key 格式 `auth:token:{token}`，TTL 2 小时；登出/禁用/重置密码时从 Redis 删除实现即时失效
12. 所有 `/sys/**` 接口必须加 `@RequiresPermission("sys:xxx:action")` 权限注解，由全局拦截器校验；权限码格式 `模块:资源:操作`（如 `sys:user:list`）
13. 白名单仅 `/auth/login` 匿名可访问；`/auth/logout`、`/auth/menus`、`/auth/password` 仅需登录不需具体权限码
14. 未登录返回 401，已登录但权限不足返回 403，两者禁止混淆
15. 异常统一抛 `ServiceException`（带 ResultCode），由全局异常处理器 `GlobalExceptionHandler` 转换，禁止 try-catch 后吞掉异常
16. 权限数据是系统预置（`sys_permission` 无维护接口），初始化用 `CommandLineRunner` 幂等执行（按权限编码已存在判断）
17. admin 角色（编码 `admin`）不可删除、不可编辑、不可改权限，默认拥有全部权限；admin 账号不可删除/禁用/重置密码/改角色
18. 删除用户级联删除其用户-角色关联；删除角色级联删除角色-权限、用户-角色关联；删除操作在 Service 层事务内完成
19. 多角色权限取并集去重；用户无角色时登录成功但返回空菜单树
20. 登录成功后菜单树与当前用户接口均需计算并集去重后的菜单树

## 注释规范（AI 编码时随代码生成）

> **注释规范见 comment-standards skill**（`standards/comment-standards.md`），AI 编码时加载并逐条对照其强制规则与自检清单。本流程不复制注释规则，避免双份维护漂移。
> 核心要求：所有类/方法/变量必须注释；方法体内步骤注释；`// WHY:` 记录非直觉设计决策。

## 公共组件规范（防重复代码，AI 编码时必须遵守）

21. 包结构约定：无状态工具类 → `com.permission.common.util/`；可继承的抽象基类/模板方法 → `com.permission.common.base/`
22. 同一逻辑出现第 2 个使用点 → 必须抽取为公共组件（工具类或抽象基类），禁止第二处复制粘贴
23. 编码前先扫描 `common/` 目录，已有可复用组件必须复用，禁止复制粘贴已有实现
24. 任务拆解"公共组件" Phase（0.5）列出的组件必须实现，使用点必须调用/继承该组件，禁止自留一份副本
25. 已知候选公共组件：`R<T>` 返回体、`PageResult<T>` 分页、`ResultCode` 枚举、`ServiceException`、`GlobalExceptionHandler`、`@RequiresPermission` 注解 + 权限拦截器、`JwtUtil`、`RedisTokenStore`、`MenuTreeBuilder`（树构建，登录与当前用户菜单两处复用）
