# 技术方案：后端接口权限校验

## 基本信息

- 功能项：#16 后端接口权限校验
- 类型：无入口（认证中间件 / 拦截器）
- 优先级：P1 | 依赖：#1（登录签发 token）、#15（权限数据初始化）

## 第零段 功能定性

- 入口形态：**无**（无 HTTP/MQ/Job，Spring 拦截器横切所有请求）→ 仅写通用章节，不写类型四段
- 业务复杂度：**中**——请求拦截 + token 校验 + 权限注解解析 + 强制改密拦截

## 通用章节

### 功能说明

通过 Spring `HandlerInterceptor` + 自定义注解 `@RequiresPermission` 实现认证与权限校验，配合 `WebMvcConfigurer` 注册，拦截所有 `/auth/**` 与 `/sys/**` 请求。

**拦截规则矩阵**：

| 路径 | token 校验 | 权限校验 | 强制改密校验 |
|---|---|---|---|
| POST /auth/login | 跳过（匿名） | — | — |
| POST /auth/logout | 必须 | — | 放行 |
| GET /auth/menus | 必须 | — | 拦截（1007） |
| PUT /auth/password | 必须 | — | 放行 |
| /sys/user/** | 必须 | @RequiresPermission | 拦截（1007） |
| /sys/role/** | 必须 | @RequiresPermission | 拦截（1007） |

**校验流程**：

1. 从 Header `Authorization: Bearer {token}` 提取 token
2. token 缺失/Redis 不存在/解析失败 → 401 未登录
3. 加载用户信息（userId/username/forceChange），写入 ThreadLocal（SecurityUtils）
4. 检查 forceChange：用户 force_change=1 且请求非 `/auth/password`、`/auth/logout` → 1007 强制改密未完成
5. 检查方法上的 `@RequiresPermission(value)`：`/sys/**` 必须有注解且当前用户权限集合（角色并集）含该编码 → 否则 403
6. 请求结束清除 ThreadLocal（afterCompletion）

**权限集合加载**：拦截器按用户从 `sys_user_role` + `sys_role_permission` + `sys_permission` 实时查询（权限预置数据量小，无需缓存；如需优化后续可加缓存，本期不做）。

### 验收场景（测试用例蓝本）

| # | 场景 | 输入/前置 | 期望 |
|---|------|-----------|------|
| 1 | 匿名访问白名单 | POST /auth/login 无 token | 放行 |
| 2 | 未登录访问受保护 | GET /sys/user/page 无 token | 401 |
| 3 | token 无效 | 伪造/过期 token | 401 |
| 4 | 登录无权限接口 | 有 token 无 sys:user:add 权限 | 403 |
| 5 | 登录有权限接口 | admin token 访问 /sys/user/** | 放行 |
| 6 | force_change 用户访问业务 | forceChange=1 访问 /sys/user/page | 1007 强制改密未完成 |
| 7 | force_change 用户改密 | forceChange=1 访问 /auth/password | 放行 |
| 8 | /sys 接口缺注解 | 某 /sys 接口无 @RequiresPermission | 视为需登录即可（按约束 #12，本期 /sys 全部接口均加注解） |
| 9 | 登出后 token 失效 | 登出后用旧 token | 401 |

### 公共组件识别（架构自检）

| # | 重复/可复用逻辑 | 使用点 | 抽取类型 | 设计 |
|---|----------------|--------|----------|------|
| 1 | @RequiresPermission 注解 + 解析 | 所有 /sys/** 接口方法 | 注解 common/base/RequiresPermission | `@RequiresPermission("sys:user:list")`，值=权限编码 |
| 2 | 权限集合查询 | 拦截器校验 | 数据访问（放 UserService/PermissionService） | `UserService.queryUserPermissionCodes(userId)` |
| 3 | 用户上下文存取 | 拦截器 + 业务（当前用户） | 工具类 common/util/SecurityUtils | `setUser()/getUserId()/getUsername()/clear()`（ThreadLocal） |

### 注释要求

- AuthInterceptor 类 Javadoc：职责、拦截顺序、401/403/1007 判定逻辑
- @RequiresPermission 注解注释：value 含义、格式 `模块:资源:操作`
- 校验流程步骤注释；强制改密拦截写 `// WHY:` 说明安全考量
