# 技术方案：用户管理

## 基本信息

- 功能项：#4 用户列表、#5 新增/编辑、#6 分配角色、#7 重置密码、#8 启用/禁用、#9 删除用户
- 类型：Controller（UserController）
- 优先级：P1 | 依赖：—

## 第零段 功能定性

- 入口形态：**有**，HTTP 请求
- 业务复杂度：**中**——列表为单表分页查询；新增/编辑/删除为多表写（级联用户-角色），含权限保护（admin）
- 跨功能项规则：admin 保护规则定义在**本方案**（用户侧），角色侧同规则见角色管理方案（两侧独立写，禁止合并状态机）

## 二、数据契约 → 入参出参 JSON + 校验规则

**入参示例**：

```json
// GET /sys/user/page?username=zhang&nickname=&status=1&pageNum=1&pageSize=10
// POST /sys/user  新增
{
  "username": "zhangsan",
  "nickname": "张三",
  "password": "abc123456",
  "status": 1
}
// PUT /sys/user/100 编辑
{
  "nickname": "张三丰",
  "status": 1
}
// PUT /sys/user/100/roles
{ "roleIds": [1, 2, 3] }
// PUT /sys/user/100/password
{ "newPassword": "abc123456" }
// PUT /sys/user/100/status
{ "status": 0 }
```

**出参示例**：

```json
// 分页
{ "code": 200, "message": "操作成功", "data": {
  "total": 2, "records": [ { "userId": 100, "username": "admin", "nickname": "管理员", "status": 1, "forceChange": 0, "createTime": "2026-08-19 10:00:00" } ]
} }
// 详情（含已分配角色）
{ "code": 200, "message": "操作成功", "data": { "userId": 100, "username": "admin", "nickname": "管理员", "status": 1, "forceChange": 0, "createTime": "...", "roleIds": [1] } }
// 用户名重复
{ "code": 1003, "message": "用户名已存在", "data": null }
// admin 保护
{ "code": 1006, "message": "超级管理员不允许该操作", "data": null }
```

**校验规则（逐字段）**：

- UserQueryDTO.username：可选，1-50 字符，模糊查询
- UserQueryDTO.nickname：可选，1-50 字符，模糊查询
- UserQueryDTO.status：可选，0/1 枚举
- UserSaveDTO.username：必填，3-50 字符，**大小写不敏感唯一**
- UserSaveDTO.nickname：必填，1-50 字符
- UserSaveDTO.password：必填，6-20 字符
- UserSaveDTO.status：必填，0/1 枚举
- UserEditDTO.nickname：必填，1-50 字符
- UserEditDTO.status：必填，0/1 枚举
- RoleAssignDTO.roleIds：可空（空=清空全部角色）
- UserPasswordResetDTO.newPassword：必填，6-20 字符
- UserStatusDTO.status：必填，0/1 枚举
- 分页参数 pageNum/pageSize：默认 1/10，pageSize 最大 100

## 三、核心逻辑 → Service 业务逻辑

- **queryUserPage**：单表分页查询（按用户名/姓名/状态条件，LambdaQueryWrapper），无业务规则
- **queryUserById**：单表查询 + 查该用户已分配 roleIds
- **saveUser**：校验用户名唯一 → 密码 BCrypt 加密 → 插入 sys_user（状态含 forceChange=0）→ 如带 roleIds 则插入 sys_user_role
- **updateUser**：查用户存在 → admin 保护拦截 → 更新昵称/状态 → 若用户名变更校验唯一（编辑不含用户名，见 DTO 无 username 字段）
- **assignRoles**：查用户存在 → admin 保护拦截 → 删除该用户全部 user_role → 逐条插入新关联（roleIds 空则只删不插）
- **resetPassword**：查用户存在 → admin 保护拦截 → 密码 BCrypt 加密更新 + forceChange=1 → 清除该用户全部 Redis token（强制下线重新登录）
- **changeUserStatus**：查用户存在 → admin 保护拦截 → **禁止禁用当前登录用户** → 更新 status；禁用时清除该用户全部 token 强制下线
- **deleteUser**：查用户存在 → admin 保护拦截 → **禁止删除当前登录用户** → 事务内删除 sys_user + sys_user_role（级联）

> **admin 保护规则（本方案定义）**：用户名或用户ID 等于内置 admin（角色含 admin）时，update/assignRoles/resetPassword/changeUserStatus/delete 均返回 1006。admin 账号不可编辑、不可删除、不可禁用、不可重置、不可改角色。

## 四、关注点 → 权限与事务

- 全部接口加 `@RequiresPermission`：GET → `sys:user:query`；POST → `sys:user:add`；PUT → `sys:user:edit`；DELETE → `sys:user:delete`
- **事务**：saveUser（多表：sys_user + sys_user_role）、assignRoles（delete + insert）、deleteUser（级联多表）必须 @Transactional(rollbackFor = Exception.class)，只放 Service 层
- **数据校验兜底**：用户名唯一索引兜底 + 代码预校验（避免并发插入重复）

| # | 场景 | 请求/输入 | 期望 |

| 10 | 分配角色给 admin | userId=admin | 1006 不允许操作 |
| 11 | 重置密码成功 | 合法入参 | 200 + forceChange=1 + 旧 token 失效 |

| 13 | 禁用成功 | status=0 | 200 + 该用户登录被拒 |

| 15 | 删除成功 | 合法 userId | 200 + 用户及 user_role 级联删除 |
| 16 | 删除 admin | userId=admin | 1006 不允许操作 |
| 17 | 删除当前登录用户 | userId=当前用户 | 1006 不允许操作 |
