# 技术方案：认证模块（登录/登出/菜单树/自助改密）

## 基本信息

- 功能项：#1 登录、#2 登出、#3 获取当前用户菜单树、#14 用户自助改密
- 类型：Controller（AuthController）
- 优先级：P1 | 依赖：#15 权限数据初始化

## 第零段 功能定性

- 入口形态：**有**，HTTP 请求（4 个接口）
- 业务复杂度：**中等**——登录/登出/改密为多表读 + Redis 写；菜单树计算为多表查询 + 树构建（并集去重）
- 跨功能项规则：菜单树构建规则定义在本方案（登录与 #3 共用），#13 全量权限树构建复用同一树构建逻辑

## 二、数据契约 → 入参出参 JSON + 校验规则

**入参示例**：

```json
// POST /auth/login
{ "username": "admin", "password": "admin123" }

// PUT /auth/password（自助改密）
{ "oldPassword": "admin123", "newPassword": "newpass888" }
```

**出参示例**：

```json
// 登录成功
{ "code": 200, "message": "操作成功", "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9...",
    "forceChange": true,
    "menus": [ { "id": 1, "permissionName": "系统管理", "permissionCode": "sys", "parentId": 0, "type": 1, "route": null, "sort": 1,
                 "children": [ { "id": 2, "permissionName": "用户管理", "permissionCode": "sys:user", "parentId": 1, "type": 2, "route": "/user", "sort": 1, "children": [] } ] } ]
} }

// 登录失败（密码错误）
{ "code": 1001, "message": "用户名或密码错误", "data": null }
// 登录失败（禁用）
{ "code": 1002, "message": "用户被禁用", "data": null }
// 自助改密旧密码错误
{ "code": 1005, "message": "旧密码错误", "data": null }
```

**校验规则**：

- LoginDTO.username：必填，1-50 字符
- LoginDTO.password：必填，非空
- PasswordDTO.oldPassword：必填
- PasswordDTO.newPassword：必填，6-20 字符

## 三、核心逻辑 → Service 业务逻辑

### 登录 login(username, password)

1. 按用户名查询 sys_user（用户名匹配大小写不敏感，`WHERE username = LOWER(?)`，字段统一存小写）
2. 用户不存在 → 抛 1001（用户名或密码错误，不区分是否存在，防用户枚举）
3. `BCryptPasswordEncoder.matches(password, dbPassword)` 校验失败 → 抛 1001
4. status = 0（禁用）→ 抛 1002
5. 生成 JWT token（含 userId、username，过期 2h），写入 Redis：
   - `auth:token:{token}` → userId，TTL 2h
   - `auth:user_tokens:{userId}` → Set\<token\>（供禁用/删除/重置时按用户批量清除）
6. 计算菜单树（见下）返回 LoginVO{token, forceChange, menus}

### 菜单树计算（登录 + /auth/menus 共用，规则定义在本方案）

1. 查该用户全部角色：`sys_user_role` join `sys_role`（过滤已删除角色）
2. 按角色查权限：`sys_role_permission` join `sys_permission`（过滤 type=1 目录 + type=2 页面），**多角色取并集去重**（按 permission_id）
3. 构建树：按 parentId 从根（parentId=0）递归组装，节点含 id/permissionName/permissionCode/parentId/type/route/sort/children，按 sort 排序
4. 用户无任何角色 → 返回空数组
5. admin 角色（编码 admin）默认拥有全部权限：加载全部 sys_permission 组装

### 登出 logout(token)

1. 校验 token 有效（拦截器已做）
2. 删除 `auth:token:{token}`，SREM 对应 `auth:user_tokens:{userId}`
3. 幂等：token 已失效也返回成功

### 自助改密 changePassword(userId, oldPassword, newPassword)

1. 查当前用户，`BCryptPasswordEncoder.matches(oldPassword, dbPassword)` 失败 → 抛 1005
2. 更新密码为 newPassword 的 bcrypt 密文，`force_change` 置 0
3. 清除该用户全部 token（SINTER `auth:user_tokens:{userId}` → 逐个 DEL → DEL key），当前会话失效需重新登录
4. 事务：单表写，@Transactional 兜底

## 四、关注点 → 权限与事务

- **接口权限**：登录匿名；/auth/menus、/auth/password、/auth/logout 仅需登录（拦截器放行，不需具体权限码）；所有接口无 @RequiresPermission 注解（认证模块属白名单）
- **强制改密拦截**：forceChange=1 的用户，除 /auth/password、/auth/logout 外其它受保护接口返回 1007（由权限拦截器统一处理，见 #16 方案）
- **事务**：login/logout 为读 + Redis 操作，无 DB 多表写，无需事务；changePassword 单表写加 @Transactional
- **安全**：密码不落日志；登录错误统一 1001（防枚举），禁用单独 1002（管理语义明确）

## 通用章节

### 验收场景（测试用例蓝本，三态）

| # | 场景 | 请求/输入 | 期望 |
|---|------|-----------|------|
| 1 | 登录成功 | admin/admin123 | 200 + token 非空 + forceChange=true + menus 含全部权限树 |
| 2 | 用户名不存在 | user/nopass | 1001 用户名或密码错误 |
| 3 | 密码错误 | admin/wrongpass | 1001 用户名或密码错误 |
| 4 | 用户被禁用 | 禁用用户/正确密码 | 1002 用户被禁用 |
| 5 | 用户名大小写不敏感 | ADMIN/正确密码 | 200 登录成功 |
| 6 | 无角色用户登录 | 新用户/正确密码 | 200 + menus 为空数组 |
| 7 | 多角色权限并集去重 | 用户 A+B 角色（权限重叠） | menus 中无重复权限节点 |
| 8 | 登出后访问 | 登出后用旧 token 请求 /auth/menus | 401 |
| 9 | 重复登出 | 再次登出 | 200 幂等成功 |
| 10 | 自助改密成功 | 旧密码正确 + 新密码 | 200 + 旧 token 失效 + 新密码可登录 |
| 11 | 自助改密旧密码错误 | 旧密码错误 | 1005 旧密码错误 |
| 12 | 强制改密拦截 | forceChange=1 用户访问 /auth/menus | 1007 强制改密未完成 |
| 13 | 强制改密后放行 | forceChange=1 用户访问 /auth/password | 200 |
| 14 | 新密码格式非法 | newPassword 长度 <6 | 400 参数校验错误 |
